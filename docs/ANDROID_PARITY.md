# Android day-planner parity acceptance checklist

Audit date: 2026-10-01. Baseline: the checked-in iOS PWA in `planner_api/static/pwa/index.html`, `app.js`, `styles.css`, `sw.js`, and `manifest.webmanifest`. Android adds a native focus timer and saved-day reading; it must retain the PWA's existing planning interactions. An API method existing in a repository does not prove that the corresponding interaction is usable in the installed APK.

This is a release checklist, not a claim that every item has passed. Check an item only after its acceptance case passes in the rebuilt APK or an appropriate automated test. Re-review this checklist after Android changes land; the initial audit found drag scheduling, Top Wins names, direct stars and inbox scheduling missing despite basic CRUD methods existing.

## Release-blocking planning interactions

- [ ] **Drag a time block to reschedule.** Hold a task, move vertically, see its candidate time and lifted state, and drop to save a five-minute snapped time. A normal early vertical movement remains scrolling; a short tap opens editing. Completion, star and focus buttons never begin a row drag. Canceling a gesture, losing capture, backgrounding, rotating or leaving the screen clears every lifted/drag state without leaving scrolling frozen. A failed save restores the previous schedule and displays the server error. Test both ordinary tasks and synthetic habit occurrence IDs. PWA: `attachDrag`, `releaseDrag`, `taskRow`.
- [ ] **Top Wins contains actual task names.** Above the timeline, show every starred task as a tappable chip, the number completed out of the number starred, and `Day won` when all are complete. Tapping a timed chip reveals the corresponding timeline row. Android should also reveal an unscheduled chip in its inbox; the current PWA chip handler only searches timed rows, so that additional inbox jump is a usability correction rather than an already working browser interaction. Completion and starring refresh this panel immediately. When tasks exist but none are starred, show the invitation to select up to five. Hide the empty invitation on a completely empty day. PWA: `renderWins`, `STAR_LIMIT`, `starButton`.
- [ ] **One-tap stars on the timeline and inbox.** Both timed rows and open inbox items offer a direct star toggle, with a visible filled state. The edit sheet also offers the toggle. Habits can be starred. The backend owns the five-per-day limit; a rejected sixth star must revert locally and explain the limit. Narrow overlap columns may move the star into the editor if space is insufficient, as the PWA does. PWA: `starButton`, `toggleStar`, `refreshSheetStar`.
- [ ] **Schedule an inbox item into the next real free slot.** A dedicated Schedule action opens an edit sheet with the existing task ID, title, duration and a computed free time; saving patches that task rather than creating a duplicate. The candidate must accommodate the entire duration, account for overlapping busy intervals, and move to the following date if it passes midnight. Canceling the sheet writes nothing. PWA: `scheduleNext`, `openEdit`.
- [ ] **Timeline expresses actual time and simultaneous blocks.** Preserve start positions, duration-height pills, time labels, dotted spine, free gaps, and columns for simultaneous work. A two-hour task must visibly occupy more time than a short block. Two or more overlapping tasks retain separate title, completion, edit and focus controls; they must not be presented as sequential work at different implied times. PWA: `render`, `computeOverlapLayout`, `taskRow`, `gapRow`.

## Dates, navigation and current time

- [ ] **Logical day rolls at 04:00.** At 01:30 on October 2, the selected logical Today is October 1 and the current position is minute 1530. At 04:00 it becomes October 2. Respect the day feed's timezone for Android's clock. Do not truncate after-midnight time values such as `25:30` into ordinary daytime positions. PWA: `getLogicalToday`, `logicalNowMinutes`, `fmtClock`.
- [ ] **Week selection and week jumps.** Show seven days beginning Monday, distinguish today from the selected day, and provide explicit previous/next week controls advancing the selected date by seven days. The selected date remains within the shown week. Show cached task-presence dots without inventing counts for days that have not been fetched. Accessible labels include the full date. PWA: `renderWeek`, `shiftDays`.
- [ ] **Day swipe.** Left/right swipes change one day; vertical scrolling and long-press task dragging do not change the date. Ignore multi-touch and clearly diagonal gestures. The PWA threshold is 70px with horizontal displacement exceeding vertical displacement by 1.6 times; Android may use density-aware thresholds with equivalent intent. PWA: `enableDateSwipe`.
- [ ] **Today and Now actions.** Provide Today when browsing another day. On Today with timed blocks, Now reveals the current-time marker, the current block, the next scheduled block, or the final block when the day has finished. The marker and ongoing block update as minutes pass; this highlight is independent of which block has a focus timer. Done tasks are not marked ongoing. PWA: `renderHeader`, `jump-now` handler, minute interval.
- [ ] **Date and completion summary.** Preserve Today/Yesterday/Tomorrow or weekday context, selected calendar date, completed/total counts, and a completion progress indicator distinct from network loading. Counts include timed and inbox items consistently. Empty days do not show a misleading progress bar. PWA: `renderHeader`.
- [ ] **Return from background.** Refresh the visible day without snapping a deliberately chosen date back to Today. On an actual logical-day rollover, follow the existing PWA rollover behavior and show the new Today. A rotation or process recreation should retain the selected day and editing context where possible. PWA: `visibilitychange` handler and `lastSeenToday`.

## Inbox, cards and edit sheet

- [ ] **Inbox remains easy to reach.** The PWA shows the inbox above the timeline and a persistent jump/count control. An Android inbox tab is an acceptable native equivalent if it is always reachable and starred-chip navigation reaches inbox items correctly. Count unfinished unscheduled items, not every historical completed item. Preserve starred-first inbox ordering, explicit completion and Schedule actions, and visible done state. PWA: `renderInbox`, `renderUnscheduledPill`.
- [ ] **Add a task.** A persistent Add action opens a new sheet with the selected date, default 30-minute duration and an optional start time. Leaving time blank creates an inbox item on that date. Do not inherit another task's stale custom duration or draft values. Blank title cannot save. PWA: `openSheet`, `sheet-save` handler.
- [ ] **Edit a task.** Tapping a row opens its title, actual scheduled date, time and duration. Rename, retime, change duration, move to another day, and unschedule a regular task. Preserve its existing ID, parent linkage and project linkage. The old day stops displaying a task moved elsewhere. Native date/time pickers should accompany text/manual input rather than requiring users to type every value. PWA: `openEdit`, `sheet-save` handler.
- [ ] **Duration shortcuts and custom duration.** Provide 15, 30, 45, 60, 90 and 120-minute choices plus custom minutes. Editing a custom-duration task shows the actual value, and opening a preset-duration task clears the stale custom value. Respect the API's 1–1440-minute bounds even if the input's step suggestions are five minutes. PWA: `setDuration`, `dur-chips`, `custom-dur`.
- [ ] **Complete and reopen a block.** A direct completion control works for normal rows, overlap columns, inbox items and habit occurrences. Done state, completion counts, Top Wins and active highlights agree immediately; a refused write restores the prior state. Regular split-session completion retains the backend's parent/group propagation. PWA: `toggleDone`, inbox completion handler.
- [ ] **Delete or skip the correct item.** Delete a regular task; skip only the selected occurrence of a habit. Remove it from all cached day views, including its after-midnight copy. A DELETE 404 means it is already gone and must remain gone. A failed delete restores the item. A native confirmation dialog is acceptable. PWA: `sheet-delete`, `forgetTaskEverywhere`.
- [ ] **Split without multiplying the budget.** Splitting a regular block retains half at its existing time and creates the remainder as an inbox session under the original parent. Splitting an existing session creates a sibling under the same parent. Total minutes remain unchanged and the original umbrella is not shown alongside its children. Habits are not split. The PWA keeps `round(total / 2)` and moves the remainder; use the same rounding if matching exact behavior. Preserve project linkage. For after-midnight blocks, verify the actual scheduled date and the displayed 24+ hour time are not both advanced twice. Test a failed second write and expose an ambiguous network result rather than claiming success. PWA: `sheet-split` handler.
- [ ] **Gap Add offers actual free time.** Only offer an Add action in gaps of at least 30 minutes. Measure the gap from the maximum end of all earlier/overlapping blocks, not simply the immediately previous task's end. Start at the next five-minute boundary at or after that end. Existing unscheduled items are not duplicated by gap creation. PWA: `render`, `gapRow`.
- [ ] **Retain card meaning.** Show category icons, recurring-task marker, split-session marker, start/end time and readable duration. Done titles are visually distinguishable, stars are visible, and long titles remain inspectable in the editor. Category matching covers the existing German, fitness, study, calls, paperwork, finances, meals, coding, writing and rest rules. PWA: `EMOJI_RULES`, `emojiFor`, `taskRow`.
- [ ] **Retain theme and legibility.** System light/dark mode works across cards, header, sheets and inbox. Stable per-task colors, rounded pills, muted metadata and the dotted timeline remain consistent with the PWA's Structured-inspired design. Typography, large system font scaling, small screens and landscape must not clip save/delete or overlap-column controls. PWA: `PASTELS`, `PASTELS_DARK`, `RINGS`, `styles.css` tokens.
- [ ] **Accessible interactions.** Label completion, stars, schedule, week controls, editor fields, close and focus actions. Expose selected date, checked/pressed states and progress values. Native Back dismisses the editor without saving; keyboard/focus navigation remains usable; touch targets remain practical. Editor contents remain scrollable above the keyboard. Browser Escape/Tab trapping has a native Back/focus equivalent. PWA: `taskRow` keyboard handler, `setSheetBackgroundInert`, sheet keydown handler, `index.html` labels.

## Responsiveness, cache and errors

- [ ] **Optimistic mutations preserve smoothness.** Timed completion, star, drag, add, edit and delete update the visible state before the server round trip. Android should make inbox completion immediate as well; the PWA inbox completion currently waits for its PATCH then reloads. A newly created draft cannot be completed, dragged or edited before receiving a real ID. Refusals restore a correct prior view and display an error; no success-only toast survives a failure. Preserve position during background reconciliation. PWA: `toggleDone`, `toggleStar`, `attachDrag`, `sheet-save`, `sheet-delete`.
- [ ] **Fast day changes and stale-response guards.** Display a cached date immediately, refresh it quietly, and warm neighboring days when idle. An uncached date must not display the old day's items under the new heading. Every asynchronous result is guarded by the requested selected date or generation; test rapid day switches while a manual refresh is in flight. PWA: `dayCache`, `goToDate`, `loadDay`, `schedulePrefetch`.
- [ ] **Mutation-aware cache.** Changes invalidate/update all affected cached dates, including moved items, split sessions and after-midnight copies. A day refresh must not paint stale cached data over an optimistic mutation while that mutation is pending. PWA: `forgetTaskEverywhere`, mutation handlers.
- [ ] **Refresh without interrupting gestures.** Foreground refresh, periodic refresh, data prefetch and minute updates never replace a dragged row or a live editor. A busy mutation may serialize conflicting writes, but it must not suppress normal day scrolling. PWA: `lastInteraction`, `dragging`, hourly interval.
- [ ] **Honest API results.** Reject HTTP failures and HTTP 200 bodies with `success: false`. Read messages/codes from both the app envelope and nested FastAPI detail. An invalid key prompts connection/key repair. A rejected sixth star, expired task ID or unavailable network is explained without silently claiming a save. DELETE 404 is idempotent success. PWA: `api`, `showError`.
- [ ] **Offline and install behavior.** Keep the iOS PWA's public shell cache, install manifest/icons, browser update flow and push support intact. Android has its own signed/installable APK and app icon rather than a service worker. Android may additionally display saved days offline and run timers offline; network-only edits must be explicitly rejected or safely queued with a truthful pending state. Changing server/account credentials clears incompatible local day caches. PWA: `sw.js`, manifest, `controllerchange` handler.

## Existing reminders and the additional focus timer

- [ ] **Reminder settings and proof.** Users can see whether notifications are enabled, grant/deny system permission, and disable this device's reminders. The PWA immediately sends a test notification after subscribing; Android should offer an equivalent test action or immediate visible confirmation. Unsupported iOS Safari tabs still explain Add to Home Screen. Native settings must never revoke another device's PWA subscription. PWA: `pushSupported`, `refreshNotifButton`, `enableNotifications`, `disableNotifications`.
- [ ] **Retain reminder semantics.** Morning brief, evening nudge and deadline rules come from the existing backend. Per-event yellow/green reminders preserve task names, start-time body, 30/5-minute leads, grace windows and replacement tag. Yellow is eligible with more than five and at most 30 minutes remaining; green is eligible from five minutes before to five minutes after the start. Values such as 25/3 minutes in tests are examples inside those windows, not configured lead times. Completed/untimed items do not notify; habits do. Each Android installation deduplicates its own delivered kinds rather than inheriting global web-push delivery history. `/v2/native/reminders` remains read-only. Test one device's prior morning/event alerts and a fresh second device. PWA push handlers and backend `ReminderService`; native `ReminderPolicy`, `Reminders`.
- [ ] **Reminder lifecycle correctness.** Rescheduling, deleting or completing a task replaces/cancels stale alarms. Re-enabling reminders must rebuild known alarms. Verify after-midnight identity and timezone handling. Local alarms and backend polling must not double-send the same kind. A 15-minute native background poll can miss short-notice remote changes compared with the PWA's server cron; document and test delivery limitations rather than claiming exact equivalence from rule parity alone.
- [ ] **Focus available on every timed block.** The Android-only start action includes task name and block duration, including overlap columns and habit/session blocks. Keep one active timer; selecting a different task asks before replacing it. Re-starting the same active block retains elapsed time.
- [ ] **Background timer remains controllable.** Pause/resume, overtime after zero, movable overlay, foreground notification and in-app controls agree. The foreground notification remains usable when overlay permission is denied. Hiding the overlay does not stop the timer; provide a way to restore it.
- [ ] **Finish has three distinct outcomes.** Continue keeps running; End stops without completing; Mark done waits for confirmed task completion before stopping. A server refusal retains the timer and exposes the error. Persist state for process loss and restore on relaunch; test monotonic elapsed time, clock changes and reboot behavior. Do not claim force-stop bypass or physical Samsung validation from unit tests.

## API contracts

All companion calls use `X-App-Key` for the configured server/user/workspace. The client must not send arbitrary tenant overrides. URL-encode task IDs; habit IDs contain colons and an occurrence date.

| Operation | Contract | Required interpretation |
| --- | --- | --- |
| Read day | `GET /v2/day?date=YYYY-MM-DD` | Envelope `data` includes `date`, `timezone`, `items`; use backend item identity and `done` rather than inventing local task rows. |
| Create | `POST /v2/day/tasks` with `title`, `date`, `start_time` or null, `estimated_minutes`; optional `parent_task_id`, `project_id`, `notes` | The response task ID replaces the pending draft ID. Blank time is inbox. |
| Edit / drag / schedule | `PATCH /v2/day/tasks/{id}` with the fields being changed | `scheduled_date` plus `start_time` saves the selected day/time. Hours 24+ are normalized to the following date by the backend; do not normalize twice. Null `start_time` unschedules a regular task. |
| Complete / reopen | PATCH with `done: true` / `false` | Habit IDs update that occurrence; split parents/sessions retain backend propagation. |
| Star | PATCH with `starred: true` / `false` | At most five starred items per actual scheduled day; backend rejection must revert the UI. A logical-day view may include a next-date spillover item, so do not reject a star solely from the total visible aggregate. Habit occurrence stars use the same endpoint. |
| Delete / skip | `DELETE /v2/day/tasks/{id}` | Habit IDs skip one occurrence. HTTP 404 is already-deleted success. Invalidate all cached copies. |
| Existing split | Create two child sessions, or shorten a session and create its sibling | Preserve parent identity, budget and project. This is a multi-request operation today; an atomic endpoint is a separate backend improvement, not a missing PWA feature. |
| Native reminder feed | `POST /v2/native/reminders` with `sent_kinds: [...]` | Up to 2000 identifiers, each no longer than 300 characters; no tenant fields. Read-only feed returns `date`, `timezone`, `reminders`. |
| PWA push | Existing `/v2/push/vapid-key`, `/v2/day/push/subscribe`, `/unsubscribe`, `/test` | Preserve browser subscription renewal/resync and iOS notifications. Native delivery uses Android channels/feed instead of browser VAPID. |

### Baseline limitations and native equivalents

The checklist distinguishes implementation gaps from optional fixes to existing browser rough edges: inbox win-chip navigation and inbox completion optimism are improvements; notes editing and an atomic split endpoint are not existing PWA features. PWA logical-day calculation uses the browser/device clock even though the feed supplies a timezone; Android should use the workspace timezone. Browser push subscription rotation and service-worker shell caching remain browser responsibilities. Android must preserve the planning behavior while using platform permissions, its own notification channel and a signed APK.

### Exact scheduling and layout cases

1. **Next free slot:** Today starts at `ceil(logicalNowMinutes / 30) * 30`; other selected dates start at 09:00. Let `need` be this inbox item's duration. For sorted occupied intervals, stop if `candidate + need <= interval.start`; otherwise, if `candidate < interval.end`, advance to that end. Carry any minute >=1440 into the date. Example: now 09:05, a 90-minute inbox item, 09:30–10:00 and 10:30–11:00 busy → suggest 11:00, not 10:00. Two-hour 09:00–11:00 overlapped by 09:30–10:00 → next gap starts 11:00.
2. **Drag:** PWA hold is 230ms; moving >10px before the hold cancels it. Pixel delta maps through 1.8 pixels/minute; candidate minutes are rounded to five. The PWA clamps visual top >=0 relative to its timeline origin and resulting minutes >=0; Android may extend scrolling bounds to support earlier times, but must not emit negative hours or invalid API data. Show the snapped candidate while dragging, commit only on a successful drop, and restore on cancellation/failure.
3. **Timeline bounds:** PWA starts one rounded-down hour before the first timed block (minimum midnight), finishes one rounded-up hour after the last end, and uses 1.8 pixels per minute with 52px minimum task height. Native density-aware scaling is acceptable if clock alignment and relative durations remain truthful. With only inbox items, no huge empty clock timeline is displayed.
4. **Overlap:** Intervals are half-open `[start, start + duration)`. Reuse the first column whose previous end is <= this start; otherwise add a column. Connected overlap groups share their maximum column count, including transitive overlaps. 09:00–10:00 and 10:00–11:00 do not overlap. 09:00–11:00, 09:30–10:00 and 10:00–12:00 occupy two columns; the short middle task does not create a third. Each column keeps independent controls and duration-height representation.
5. **Logical rollover:** Test 03:59 and 04:00; manual day browsing remains stable on an ordinary resume. Test a 01:30 occurrence shown as 25:30 on the previous logical day, its completion/star identity, date edits, split remainder dates, and cache invalidation.

## Required evidence before declaring parity complete

- [ ] Rebuilt APK corresponds to the source reviewed and to the documented package/version and retained signing identity.
- [ ] Automated tests cover scheduling/overlap/drag math, five-star refusal rollback, CRUD/draft failure, selected-day races, API-envelope failure and timer/reminder policy.
- [ ] Rendered UI review covers light/dark, small width, long titles, multiple overlap columns, keyboard-open editor, and Top Wins/inbox navigation.
- [ ] Device/emulator interaction demonstrates hold-drag-drop, tap edit, vertical scroll, day swipe, split, next-free schedule, presets/pickers and completion from overlap rows.
- [ ] Background overlay/notification controls and permission-denied behavior are tested; Samsung physical-device limitations remain explicit until validated on the user's S24 Ultra.
- [ ] PWA's existing JavaScript/service-worker regressions remain passing; Android work does not remove or replace the iOS interface.

Browser-specific service-worker subscription rotation, offline shell update and browser notification installation guidance remain PWA obligations. Their native equivalents use the Android app lifecycle, APK updates, platform permissions and local channels; parity means preserving the user's planning behavior and reminder intent, not embedding the browser implementation in Android.
